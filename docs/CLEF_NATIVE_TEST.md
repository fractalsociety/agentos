# Clef-Flash native seL4 experiment

This opt-in experiment executes Clef-Flash's complete 32-layer Qwen3.5
backbone and six-layer decision head in a native seL4 protection domain.
The inference engine is Rust, built without `std`. A small C adapter uses
the existing native client's block queue and diagnostic interface.

The fixture asks whether to grant a 512 MiB allocation when only 256 MiB
is available. Its 163 input tokens and question/option spans are fixed in
`tests/fixtures/clef-resource-choice.h`. Every native run computes the
hidden states, option logits and probabilities from the model weights.
The input fixture contains reference probabilities for comparison, not
intermediate activations or substituted inference results.

The [2026-10-07 native receipt](evidence/2026-10-07-clef/native.json) records
a passing x86_64 QEMU/KVM run. Boot, model loading and inference completed
in 182.1 seconds, excluding host download/hash verification and disk staging.
The [retained serial lines](evidence/2026-10-07-clef/serial.txt) show every
layer and native probabilities of 904456 and 95543 parts per million.
`make test-host` and `make gate` also passed with SDK 2.3.0.

## Reproduce

On this Linux x86_64 host, with KVM, QEMU, C/LLVM tools, Cargo, curl, tar and
the existing Microkit SDK 2.3.0 installed:

```
make clef-fetch GUEST_OS=none
make test-clef-unit GUEST_OS=none
make clef-host-check GUEST_OS=none
make clef-native-test GUEST_OS=none
```

The native target downloads a pinned Rust toolchain into the user cache,
builds the guest-free seven-PD composition, and cold-boots the unchanged
SDK debug kernel with QEMU/KVM. QEMU is configured with 12 GiB RAM and one
vCPU. Reserve at least 16 GiB available host RAM and 15 GiB disk space.
Root fixes the inference CPU budget at 5 ms per 10 ms and the block driver
and virtualizer at 1 ms per 10 ms each. These are boot-time allocations;
the model has no authority to increase them.
Loading through the existing secondary block driver takes several minutes.
The launcher imposes a one-hour overall timeout and kills QEMU afterward.

Model weights stay in `~/.cache/agentos/clef-flash/`. The experiment stages
an aligned disposable copy under `build/clef-native/model.img`, attached
read-only. It uses no physical disk. Root maps three private memory regions
totaling 8 GiB; the final 1 GiB is the Rust allocator's fixed arena. The
remaining space holds the model and alignment gaps. Missing mappings stop
startup. No guest VMM, Linux guest or hosted inference service runs inside
this composition.

`build/clef-native/serial.log` records loading, all 32 backbone layers, two
routing layers, four joint layers and both probabilities. A passing run
ends with `CLEF_NATIVE_PASS` and writes `receipt.json` with kernel, root
image, inference PD and model hashes. The launcher rejects a pass marker
without the complete layer log. It clears prior logs and receipts before
boot, and a lock prevents concurrent runs in the same directory.

The reference assigns `defer` probability 0.908079603 and `grant`
0.091920397. The Rust host implementation produces 0.904456437 and
0.095543578. Acceptance requires choosing `defer`, finite scores, and
absolute probability error at most 0.02 for each option. The native
implementation dequantizes weights to float for CPU multiplication;
llama.cpp uses optimized quantized kernels, so bitwise equality with that
independent oracle is not required. This is a numerical smoke test, not a
decision-quality benchmark or a calibrated confidence guarantee.

The fixed token fixture was generated by `make clef-fixture` against a
loopback llama.cpp reference server at port 18081. It checks that the
reference's input-token count matches the segmented prompt encoding.
The exact request, response, tokens, spans and provenance are retained in
`tests/fixtures/clef-resource-choice.json`. The native test needs neither
that server nor any host tokenizer at runtime.

## Rust and isolation boundaries

Model metadata and tensor access use checked slices; the forward pass
uses Rust-owned vectors. The parser rejects unsupported tensor layouts,
duplicate names, overflows and truncated data. The API accepts one choice
question, 2–4 options and at most 512 tokens. The allocator uses fixed
metadata over private mapped RAM and rejects exhaustion. Panics fail the
test; they do not unwind into C.

Unsafe code is confined to the C ABI entry, the private arena allocator,
the compiler's memory comparison intrinsic, and small checked SSE2 math
routines. The custom target describes an x86_64 user-mode PD with SSE2 and
no red zone or AVX. Its Rust `core` and `alloc` are rebuilt for that target
using pinned Rust 1.98.1 and Cargo's unstable `build-std`/JSON-target
options (`RUSTC_BOOTSTRAP=1` for this isolated toolchain). The seL4 kernel
is not rebuilt or modified. This avoids mixing the stock bare-metal
target's software-float ABI with hardware-float objects.

## Qualification limits

This test covers a single text prompt, Q4_K_M weights, CPU inference and
an advisory memory choice. It does not implement a native tokenizer,
multiple simultaneous questions, image inputs, GPU inference, runtime
telemetry, resource enforcement, deadlines inside the PD, or physical-PC
boot acceptance. The model owns no device frames or IRQs and cannot change
seL4 scheduling/capability policy. PRD Test 008 still requires competing
tasks, enforced allocations, fault recovery and persisted receipts.

Run `make test-host SEL4_SDK_VERSION=2.3.0` and
`make gate SEL4_SDK_VERSION=2.3.0` for repository regression checks; the
large-model native test remains opt-in.
